移動平均濾波Moving Average

把每個點換成「它附近 N 個點的平均」，雜訊互相抵消，訊號就變平滑了。

原理

白雜訊有正有負，平均起來會趨近 0；真實訊號在短時間內變化不大，平均後幾乎不變。所以「取平均」能留下訊號、壓掉雜訊。

因果（causal）： y[n] = ( x[n] + x[n-1] + … + x[n-N+1] ) / N 置中（centered）：y[n] = ( x[n-k] + … + x[n] + … + x[n+k] ) / N, N = 2k + 1

x 是輸入、y 是輸出、N 是視窗長度。平均 N 個獨立雜訊後，雜訊標準差約降為原本的 1/√N。

因果 vs. 置中

因果版本只用「現在與過去」的資料，可以即時運算，但輸出會落後約 (N−1)/2 個樣本。置中版本用到「未來」的資料，沒有延遲，但只能在錄完資料後離線處理。

常見誤區：視窗越長不一定越好。N 太大時，步態的波峰也會被一起「平均掉」，峰值變矮、時間點也會偏移。

參數怎麼調

參數意義調大會怎樣建議起始值
視窗長度 N每次平均幾個點更平滑，但波峰被削平、延遲變大fs = 100 Hz 時 5～15 點（50～150 ms）
計算方式因果或置中—離線分析用置中；即時系統只能用因果

優點與限制

👍 優點

  • 概念最簡單，幾行程式就能寫完
  • 用累加和實作，每個樣本只需 O(1) 運算
  • 對白雜訊效果好，是「平滑」最好的基準線（baseline）

⚠️ 限制

  • 頻率響應有明顯的旁瓣（sidelobe），高頻雜訊壓不乾淨
  • 突波（spike）會被「攤平」成一個小鼓包，而不是被移除
  • 因果版本有固定延遲，會讓事件偵測時間點偏後
  • 視窗長度只能是整數，調整不夠細

在步態訊號中的應用

在 IMU 步態分析裡，移動平均常用在快速檢視資料或計算包絡線，例如把加速度的絕對值做 0.5～1 秒的移動平均，用來判斷受試者是在「走路」還是「站著」。

要偵測足跟著地（heel strike）這類精確時間點時，不建議用因果移動平均：N = 15、fs = 100 Hz 會造成約 70 ms 延遲，對步態週期約 1 秒的訊號來說是 7% 的誤差。

Python 實作

import numpy as np

def moving_average(x, window=15, mode="causal"):
    x = np.asarray(x, dtype=float)
    kernel = np.ones(window) / window
    if mode == "centered":
        # 置中：與 demo 相同，邊界用實際可用的點數平均
        num = np.convolve(x, kernel * window, mode="same")
        cnt = np.convolve(np.ones_like(x), np.ones(window), mode="same")
        return num / cnt
    # 因果：只用過去的資料
    csum = np.cumsum(np.insert(x, 0, 0.0))
    y = np.empty_like(x)
    for n in range(len(x)):
        lo = max(0, n - window + 1)
        y[n] = (csum[n + 1] - csum[lo]) / (n + 1 - lo)
    return y

fs = 100
t = np.arange(0, 6, 1 / fs)
x = np.sin(2 * np.pi * 1.0 * t) + 0.25 * np.random.randn(t.size)
y = moving_average(x, window=15, mode="centered")
