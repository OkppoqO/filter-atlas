中值濾波Median Filter

用「中位數」取代「平均」，一兩個離譜的點完全影響不了結果。

原理

把視窗內的 N 個點排序，取正中間那一個。突波（spike）的值通常特別大或特別小，排序後會被擠到兩端，根本選不到它。

y[n] = median( x[n−k], …, x[n], …, x[n+k] ), N = 2k + 1

舉例：視窗內是 [0.9, 1.0, 5.0, 1.1, 1.0]。平均是 1.8（被 5.0 拉高），中位數是 1.0（完全不受影響）。

中值濾波是非線性的：兩個訊號相加後再濾波 ≠ 各自濾波後再相加。因此它沒有頻率響應可以畫，也不能用「截止頻率」來描述。

常見誤區：中值濾波對「白雜訊」的效果其實不如移動平均。它的專長是突波，不是一般雜訊；兩種雜訊都有時，常見做法是先中值、再低通。

參數怎麼調

參數意義調大會怎樣建議起始值
視窗長度 N每次取幾個點的中位數（奇數）能移除更寬的突波，但波峰會被削成平頂突波寬度的 2 倍以上再加 1；單點突波用 3～7

優點與限制

👍 優點

  • 對突波、脫落點（dropout）幾乎完全免疫
  • 能保留訊號的「邊緣」（階梯狀的快速變化），不會被抹成斜坡
  • 置中版本沒有延遲

⚠️ 限制

  • 需要排序，運算量比移動平均大
  • 對高斯白雜訊的效果比線性濾波器差
  • 視窗太大會把尖峰削成平頂，峰值數值失真
  • 非線性，無法用頻域工具分析或設計

在步態訊號中的應用

藍牙 IMU 偶爾會發生封包遺失或通訊錯誤，造成單一樣本跳到很大的值。這類錯誤用低通濾波只會被攤平成一個鼓包，用 N = 5 的中值濾波則能直接去掉。

建議的前處理順序：中值濾波（去突波）→ Butterworth 低通（去白雜訊）→ 步態事件偵測。順序反過來的話，突波會先被低通攤開，中值濾波就救不回來了。

Python 實作

import numpy as np
from scipy.ndimage import median_filter

fs = 100
t = np.arange(0, 6, 1 / fs)
x = np.sin(2 * np.pi * 1.0 * t) + 0.25 * np.random.randn(t.size)

# 加入幾個突波
idx = np.random.choice(t.size, 12, replace=False)
x[idx] += np.random.choice([-1, 1], 12) * 2.5

# mode="nearest"：邊界用最靠近的值補齊
# （demo 是在邊界縮短視窗，兩者只有頭尾幾個點不同）
y = median_filter(x, size=7, mode="nearest")
